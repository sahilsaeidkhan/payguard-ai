# PayGuard AI 🛡️

**AI payment-risk copilot for small sellers — PayPal AI Hackathon 2026 entry.**

A small seller wants to know, *before shipping*, which incoming PayPal payments
are risky (likely fraud / dispute / chargeback) — and why, in plain language,
not a black-box score. PayGuard scores every payment with an XGBoost model,
explains the top risk factors per transaction, and recommends HOLD / REVIEW /
APPROVE in a risk-ranked seller queue.

## How it works

1. **Transactions in** — three ways: a demo queue of seller transactions, a
   **CSV upload** (`POST /upload-csv`, or the dashboard's upload section —
   only an `amount` column is required; PayPal-export headers like
   `gross_amount` and `transaction_id` are accepted, see
   `payguard/ingest.py`; try `GET /sample-csv`), and a **live PayPal
   sandbox order** (`POST /paypal/order` — creates a real sandbox order via
   the PayPal Orders API and scores it end-to-end; needs free sandbox
   credentials, see below).
2. **XGBoost risk model** — trained on transaction features: amount vs the
   seller's average order value, buyer account age, buyer order history, order
   velocity, country/currency mismatch, digital-goods flag, buyer dispute
   history. Training data is generated by documented rules in
   `payguard/data.py` (real seller payments can't be used in a demo).
3. **Explainable output** — per transaction, the top contributing factors,
   measured from the model itself: each feature is replaced in turn by the
   safe-seller baseline and the drop in the model's risk score is that
   factor's contribution (see `payguard/model.py:explain`), plus a
   plain-language summary, e.g. *"High risk: new buyer account,
   amount well above your usual order value, billing and shipping countries
   differ."*
4. **Seller dashboard** — Streamlit risk queue with HOLD / REVIEW / APPROVE
   actions that are recorded in a decision log (`POST /decisions`,
   `GET /decisions` — counts by decision, most recent first), plus a
   "score a single payment" form.

## Quickstart

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python train.py            # trains the XGBoost model, prints metrics
python -m pytest tests/ -q # smoke tests (model + API)

# API
uvicorn payguard.api:app --reload        # http://127.0.0.1:8000/docs

# Dashboard
streamlit run payguard/dashboard.py
```

## API

- `GET /health` — status + model metrics
- `POST /score` — score one transaction (JSON, see `payguard/api.py`);
  inputs are validated, so bad payloads get a clear 422 (negative ages,
  out-of-range flags/hours, zero amounts) instead of a nonsense score
- `GET /transactions` — the scored demo queue
- `GET /model` — features, importances, metrics
- `POST /upload-csv` — score every row of an uploaded transaction CSV, riskiest first
- `GET /sample-csv` — an example CSV in the accepted format
- `POST /decisions` — record a seller decision (HOLD / REVIEW / APPROVE) on a payment
- `GET /decisions` — decision log + counts by decision
- `GET /paypal/status` — sandbox wiring status (never exposes credentials)
- `POST /paypal/order` — create a live PayPal sandbox order and score it
  (returns the order id, status, buyer-approval URL, and the risk score)

Example:

```bash
curl -X POST http://127.0.0.1:8000/score \
  -H 'Content-Type: application/json' \
  -d '{"amount": 400, "seller_avg_order_value": 55,
       "buyer_account_age_days": 2, "country_mismatch": 1,
       "buyer_disputes_90d": 2}'
```

## PayPal sandbox setup (free, no KYC)

1. Create an app at [developer.paypal.com](https://developer.paypal.com)
   (Sandbox) and copy its Client ID + Secret.
2. `export PAYPAL_CLIENT_ID=... PAYPAL_CLIENT_SECRET=...`
3. Start the API, then `curl -X POST http://127.0.0.1:8000/paypal/order
   -H 'Content-Type: application/json' -d '{"amount": 120, "currency": "USD"}'`
   — you get a sandbox order id, an approval URL, and a risk score.
   Without the credentials, `/paypal/status` reports `configured: false`
   and `/paypal/order` returns 503 with setup instructions.

## Judging-criteria map (PayPal AI Hackathon)

- **Technological Implementation:** real XGBoost model + FastAPI + Streamlit,
  not a mockup; real PayPal Orders API calls are the product's input.
- **Design:** a complete seller workflow (queue → explanation → action →
  recorded decision log).
- **Potential Impact:** chargebacks and fraud are a real, quantified cost for
  small sellers; the tool acts before shipping, when prevention is possible.
- **Innovation:** explainable risk + plain-language agent summary, not just a
  score.
- **Presentation:** end-to-end demo (queue, single-payment scoring, API docs).
